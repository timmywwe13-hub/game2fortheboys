# Contributing to Tower Defense

Thank you for your interest in contributing to Tower Defense! This document provides guidelines and instructions for contributing.

## Getting Started

1. **Fork** the repository
2. **Clone** your fork locally:
   ```bash
   git clone https://github.com/YOUR-USERNAME/video.git
   cd video
   ```
3. **Create a branch** for your feature or fix:
   ```bash
   git checkout -b feature/your-feature-name
   ```

## Making Changes

### Code Style
- Keep your code clean and readable
- Use meaningful variable names
- Add comments for complex game logic
- Follow the existing code style in `game.js`, `style.css`, and `index.html`

### Testing
- Test your changes in multiple modern browsers (Chrome, Firefox, Safari, Edge)
- Test on both desktop and mobile (use browser DevTools)
- Ensure all keyboard shortcuts still work
- Verify wave progression and enemy spawning

## Submitting Changes

1. **Commit** with clear, descriptive messages:
   ```bash
   git commit -m "Add feature: [brief description]"
   ```

2. **Push** to your fork:
   ```bash
   git push origin feature/your-feature-name
   ```

3. **Open a Pull Request** with:
   - A clear title describing the change
   - A description of what changed and why
   - Screenshots/videos if UI changes were made
   - Any relevant issue numbers (e.g., "Fixes #123")

## Types of Contributions

### 🐛 Bug Reports
- Describe the bug clearly
- Steps to reproduce
- Expected vs actual behavior
- Screenshots if applicable

### ✨ Feature Requests
- Describe the feature and its benefit
- Use cases or examples
- How it fits with the existing game

### 📝 Documentation
- Improve README clarity
- Add tips or strategies
- Document game mechanics

### 🎮 Game Balance
- Suggest tower rebalancing
- Enemy difficulty adjustments
- Map improvements

## Questions?

Feel free to open an issue with the label `question` if you have any questions!

Happy contributing! 🎮
